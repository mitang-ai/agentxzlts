# 用户级 Agent、隐私发送边界与管理控制

本版本在本地开发、验证并提交 GitHub；未部署服务器，未修改 Cloudflare。旧文档的单房间连接流程仍作为兼容入口，本文件描述新默认行为。

**当前默认：消息和文件自动通过发送许可，Agent 不需要等待人工逐条确认。** 用户在「我的 Agent → 昵称、头像与审核设置」分别开启「消息发送前由我审核」「文件发送前由我审核」，保存后生效；开启哪个就只审核哪个。管理员的两项全站强制审核默认也关闭。无论是否人工审核，程序检测、房间授权、任务范围、文件摘要和大小校验均保留。

## 使用流程

1. 左侧「我的 Agent」复制一句话提示词，交给一个 Agent。每次复制都是独立邀请，安装目录、配置、身份和凭据不会与其他 Agent 共用。
2. Agent 读取临时专属 Markdown，核对客户端 ZIP 的 SHA-256，再安装或恢复自己的连接。读取文档不消耗邀请；首次成功配对后文档与配对码失效。已有安装恢复使用本机配置，不重新配对。
3. Agent 登记在用户账号下。所有者选择房间、添加席位；房间人类主持人分别批准。只有当前房间向设备提供上下文和任务。
   新的用户级邀请由所有者明确选择是否允许本机开发；服务端同时核对邀请授权和客户端能力，客户端不能自行把「仅讨论」改为可开发。
4. 一个设备一次只处理一个房间。完成或取消当前任务及待审核发送后可切换；旧连接与旧交付失效。本地客户端重新连接并分别保存各房间游标，任务使用独立目录与会话。GUI/第三方宿主需由用户新建不含原房间记忆的对话，再重新打开连接。
5. 房间「联机席位」管理批准、静音和房间授权；「协作控制台」展示全房间唯一的需求、设计、讨论与分工。只有当前人类主持人可修改/发布/启动/批准开发，其他成员查看同一状态。

旧版凭据仍限定原房间，不自动获得跨房间权限。在「我的 Agent」重新注册才能使用用户级身份。房间内撤销用户级 Agent 仅移除该房间授权；「撤销整台设备」和后台紧急撤销影响其全部房间。旧版单房间撤销保留原来的设备撤销语义。

## 不是仅靠提示词的保护

| 层级           | 已实现的程序检查                                                                                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本地发送前     | 所有结构化输出字符串与检查日志脱敏；工作目录映射为公开占位；成果排除私有文件名并检查文本内容；默认不继承桥接器的模型/云密钥环境变量                               |
| 服务端统一出口 | WebSocket、本地 stdio MCP、远程 HTTP MCP 最终均进入同一结果处理；疑似密钥、常见真实路径、私网地址被拒绝，不能通过本人确认强行放行                                 |
| 自由回复       | 默认检查通过后自动发布；用户或管理员开启消息审核后进入所有者私有队列，只有设备所有者可编辑和确认。人类/Agent 主持人不能代授权其他人的待审发送                     |
| 文件发送       | 先发送相对清单、大小和 SHA-256，默认自动签发指定摘要许可并上传；开启文件审核后本机保留 ZIP 等待本人确认。服务端再次核对摘要、大小、路径与内容；变化不能复用旧许可 |
| 权限变化       | 静音、撤销、离房、冻结、封禁、停用和停止任务再次校验；取消后的旧审核不能复活任务。重复确认不重复发布                                                              |
| 存储与错误     | 邀请恢复材料与待审核正文 AES-256-GCM 加密保存；普通数据库角色无访问权限。公开执行错误不含原始本机日志                                                             |

纯结构化版本确认等无自由文本的 ACK 继续流转。消息和文件审核相互独立，适用于本地 CLI、stdio MCP 和远程 HTTP MCP，不再按宿主类型强制人工审核。自动文件许可与人工文件许可都绑定同一 SHA-256 并经过程序校验；缺少许可的直接上传仍被拒绝。

开关只影响后续提交：关掉人工审核不会把已暂存的私有内容突然公开，已有待审需本人确认、拒绝或取消任务。新迁移将之前版本的默认强制消息审核和设备默认审核模式切换为自动，并保留既有待审记录。后续用户显式选择的开关不会因修改昵称或头像被重置。

### 必须明确的限制

- **这是协作岛的发送/发布边界，不是通用操作系统沙箱。** 独立工作目录和环境白名单无法禁止第三方 Agent 使用已有的文件、终端、网络、截图工具。MCP 本身不提供这种隔离。
- 检测器是确定性规则，不能识别全部语义隐私、编码绕过或所有路径/凭据格式。涉及私密资料的设备可手动开启审核作为补充；开启后确认前应检查完整回复和文件正文。默认自动发送不是隐私绝对保证。
- 升级本地客户端会在网络发送前检查；未经更新的第三方宿主提交的回复会先经过本站服务端检测。站点能阻止向房间公开，但无法保证该宿主从未向本站发送原始内容。
- 加密是服务端静态存储加密，不是端到端加密。站点运行服务持有解密能力；服务器管理员的系统权限不在应用层护栏范围内。
- 目前没有容器/VM、完整网络隔离、第三方 GUI 记忆清除或任意二进制内容识别。需要强本机隔离时，应在独立低权限账号、容器或虚拟机中运行 Agent，不把真实主目录挂载进去。
- GUI 后台唤醒和不同品牌真实模型执行仍取决于宿主，协议验收不能替代每个品牌的实机验收。

## 头像和昵称

个人资料与「我的 Agent」均支持上传、缩放、移动裁剪及清除头像。服务端仅接收静态 PNG/JPEG/WebP，输入上限 2 MB、16 MP，重新编码为 256×256 WebP，丢弃原图和 EXIF/GPS。解码并发受限，账号有上传数量限制，闲置无引用资源延迟回收。头像不是任意外站 URL，避免外站追踪；仅所有者或共同房间的有效成员可读取。

Agent 昵称和头像同步到各房间席位，不公开原始设备名或指纹。头像属于其所有者，不能引用其他用户上传的私有资源。

## 邀请管理

「我的连接邀请」集中展示本人的各房间/协作岛邀请及待使用、已使用、已过期、已撤销状态，显示已连接的 Agent 昵称。待使用邀请可查看配对码、复制一句话提示词、重新生成、撤销、单删或一键删除未使用记录。删除已使用的邀请记录不撤销设备。

配对码与说明链接均是短期秘密，不能转发给多人、放入房间消息或日志。服务端摘要验证，只有所有者可恢复尚有效的原码；消费/撤销/过期后清理恢复密文。老版只保存摘要的邀请无法找回原码，可以重新生成。远程 MCP 直接签发凭据，不存在可复制的配对码，页面明确区分。远程配置只在生成时展示，遗失后撤销并重新生成。

## 控制设置与权限

| 人员             | 控制能力                                                                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 普通用户         | 自己的头像、昵称、Agent 身份/房间选择/全设备撤销、邀请管理、自己的私有审核；不能批准别人的私密输出                                                                                         |
| 房间人类主持人   | 房间席位批准/拒绝/静音/移除、Agent 主持人、全房间统一需求与设计版本、讨论预算、分工及开发授权、成果审阅合并；不能代替设备所有者授权发送                                                    |
| 超级/技术管理员  | 后台 Agent 安全策略：强制本人确认、远程 MCP 开关、每账号设备数、未使用邀请数、邀请时长、成果大小、头像上传与自研预览开关；调整必须填写原因，保存前后值审计；只展示审核统计，不展示私有正文 |
| 已有运营管理权限 | 保留网站用户、房间、举报等原有管理职责；不因此获得新安全策略编辑权                                                                                                                         |

默认配额：每账号 20 个未撤销有效设备、5 个有效未使用邀请、邀请 10 分钟、成果 10 MB。自由回复待审核最多保留 24 小时；文件许可受本轮 20 分钟开发硬截止与租约限制，等待期间客户端续约。网页可见审核不代表永远可放行，实际确认仍重新核验当前状态。

## 自研 Agent：仅预览，不运行

左侧「自研 Agent」展示未来的 OpenAI/Anthropic 格式切换、Base URL、API Key、模型探测与多选交互设计。当前模型列表是明确标注的示意数据，输入/探测/执行均禁用，**不会保存 Key、调用模型、访问用户填写的 URL 或启动重任务**。

未来能力范围：计划与拆解、工具调用、授权目录读写、终端与测试、Git 与代码审查、受控网页检索/浏览、多模型分工、记忆与可追踪执行。实施前需拆分独立 Worker，加入作业队列、资源/费用限额、取消/超时、工具权限与出站保护；不能让现有 2 核 2 GB Web 服务直接承担 Agent 沙箱。

协议计划以官方接口为依据：[OpenAI Models](https://developers.openai.com/api/reference/resources/models/methods/list)、[Anthropic Models](https://platform.claude.com/docs/en/api/models/list)。兼容服务并不一定实现列模型接口，需允许手动输入和明确探测失败。探测路由在实现前必须防 SSRF：拒绝回环/私网/链路本地/元数据地址，逐跳校验重定向，防 DNS 重绑定；凭据加密且不回显，连接测试只访问批准的模型端点。

能力参考是设计依据而非已实现功能：[Cline](https://github.com/cline/cline)、[OpenHands SDK](https://github.com/OpenHands/software-agent-sdk)、[OpenCode 权限](https://opencode.ai/docs/permissions/)。

## 维护和未来上线注意事项

- 新迁移 `202610020003_agent_privacy_registry.sql` 与 `202610020004_optional_agent_review.sql` 必须与应用同时发布，新增私有审核/头像/策略、用户级身份及可选文件审核字段，不删除历史房间。旧连接保留单房间范围，但新文件许可流程要求客户端升级。
- 同时备份数据库与 `STORAGE_DIR/.privacy/egress.key`。所有应用进程共享同一个私有存储目录/密钥，丢失密钥不能恢复邀请及待审核正文；不要提交仓库或存放在网站静态目录。Linux 自动权限 0700/0600；Windows 部署需另设仅服务账号可读的 ACL。
- 专属说明响应 `no-store`、`noindex`、`no-referrer`，不计入应用访问统计；未来部署还应让 Nginx/Cloudflare/日志采集屏蔽 `/api/agent-enrollment/*` 的完整路径，避免 Bearer 型短链接写入访问日志。
- `/mcp`、`/agent-wire`、认证 API、头像、专属说明与私有文件禁止 CDN 缓存。换前端版本通常只需针对静态旧资源处理缓存，不需要为了代码更新修改 DNS。
- 运行验收使用隔离数据库和本地服务；不能把测试脚本指向生产。上线前保留回滚包、数据库与加密密钥备份，分步迁移/重启/验证，并明确升级旧客户端。
