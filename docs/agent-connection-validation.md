# Agent 连接修复验收记录

## 范围与结论

本记录描述发布前的隔离验收：基于 `ef54e10f302b4f879ee544cc212c7686bfdcd97d` 的本地工作树检查和修复注册、审批、配对、客户端生命周期、在线状态、任务交付、房间切换及撤销的相关链路。验收阶段未更新生产服务器、Cloudflare 或 GitHub，没有升级依赖。新增一个非破坏性迁移 `202610030001_command_lock_order.sql`，统一房间与限流锁顺序；没有改写旧迁移。原有未提交的 `scripts/setup/io.mjs` 保持原样，Linux 测试副本使用该文件的 HEAD 版本。

修复和架构评估见 [连接修复与维护](agent-connection-reliability.md)。本记录不是每一种商业 Agent、模型账号、真实 GUI 对话或公网部署的验收证明。

## 关键回归

- 主持人能看到其他用户申请加入自己所有房间的 Agent；普通成员、外人不能审批，也看不到设备所有者的私有发送审核正文。
- 房间中无新建配对/MCP 入口，旧创建接口拒绝新房间级身份；旧邀请重新生成后改为用户级邀请。
- MCP 只有连接、没有任务消费者时不显示可接任务的在线状态；等待超时后才准备好的任务，未交付宿主不能冒充正在执行。
- 后台客户端空闲后收到点名能启动自己的执行接口并最终回传；重复运行原配置不会增加设备连接。此项的模型程序是 fixture。
- 两个实际 MCP stdio 子进程共享一个设备 WebSocket；只有唯一消费者可领取/回传，另一个不能代答；关闭工具窗口不终止设备后台服务。
- 房间切换先完成旧上下文清理，再轮询新房间；旧 MCP 代理不能领取新房间任务；重启后台实例后旧代理不能静默复用。
- 主动心跳发现从大厅加入房间时，WS 错误仍包含 `CONNECTION_REPLACED`。修复前同一断言确认缺失该字段；修复后不再把有效设备当成凭据撤销，原身份重连并完成房间切换。
- 讨论与开发文件按房间/任务 UUID 隔离；非法标识、中间 symlink/junction 和不同内容的已有文件被拒绝；旧在途任务保留原工作目录和基线记录。
- 同步撤销、添加房间和连接时使用锁后的状态；撤销后不再创建新席位。断线与硬删除房间不死锁，多房间授权集合变化时回滚而非反向补锁。
- 实际 Gateway `complete` 与同账号人类 `profile` 并发，修复前以测试闸门稳定复现 `40P01`，修复后两条操作都成功且最终消息只有一次。跨房间资料更新遇到新房间时以 `40001` 整体回滚，重试才更新完整集合，不消耗失败操作的限流额度。闸门仅在隔离数据库测试中临时加入，测试结束恢复原函数；最终全量单元测试的数据库日志无死锁记录。
- 清缓存和归档默认预览，拒绝活锁、链接和越界目标；归档保留凭据与成果，不按陈旧 PID 或进程名杀其他程序。
- 默认自动消息/文件发送仍然可用，可选人工审核、头像裁剪、房间统一协作设置和普通聊天功能通过原有回归。

## 重放检查

在独立数据库和存储中安装全部 16 个迁移，配置本机 `DATABASE_URL`、`APP_ORIGIN` 和 `STORAGE_DIR`。禁止把下列测试环境指向生产。按仓库脚本执行 `npm test`、`npm run typecheck`，在 Web 工作目录执行 Next 的 `build --webpack`，启动网站后设置 `E2E_BASE_URL` 运行 `npm run test:e2e`。Windows 另运行 `npm test -- tests/client-lifecycle.test.ts tests/host-adapter.test.ts`。

真实用户客户端升级后还应重放以下最小业务流程：

1. 所有者在「我的 Agent」取得新邀请，用当前产品自己的 CLI/ACP/执行接口安装；复用原正确身份配置，不复制其他人的配置。普通 MCP 只能作为手动工具，不当作自动联机成功。
2. 所有者把设备添加到两个房间；两位主持人在自己的「待我确认 · 房间入席」批准，普通成员不得批准。房间页面只有席位管理，不创建另一份安装。
3. 用同一固定配置 `start --background`，关闭安装对话，确认客户端仍连接；空闲后在当前房间 @ 它，核验任务最终完成且只出现一次回复。
4. 重复启动原配置，确认仍是一个后台实例、一个设备身份、一个任务消费者；本机 `status` 不得只凭旧 PID 文件报告成功。
5. 完成或取消在途任务，再切换已批准房间；文件只写入对应房间/任务目录，旧 MCP 会话需重启专属服务并新建对话，不能读取新房间任务。
6. 撤销单个房间只撤销该授权；撤销整台设备则原凭据不可用，其他人的设备不受影响。停止与清理只处理这个安装。

正式发布需要备份、部署服务端并执行新迁移，再按身份更新本地客户端；仅更新网页不能修复旧后台进程。本记录不替代生产发布验收。

## 仍需区分的限制

普通 MCP 无法主动唤醒现有 Codex、WorkBuddy、豆包等 GUI 对话。自动联机使用独立后台执行会话，不是接管用户已有聊天。未实测每一种商业宿主的真实模型权限、额度、网络与插件行为，不能由 fixture 成功推断它们都兼容。

旧客户端需要设备所有者更新一次；网页升级不能清掉远端电脑的旧进程和存储。当前一个设备只有一个当前房间，未实现跨房间并行调度，也未安装系统开机自启。目录与上下文隔离不是操作系统强沙箱。上述边界没有被更强的提示词或假心跳掩盖。
