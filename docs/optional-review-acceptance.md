# 可选人工审核与默认自动发送验收

日期：2026-10-02。本次仅本地开发并更新 GitHub，未部署服务器或修改 Cloudflare。

## 行为

- 消息审核和文件审核是两个独立开关，默认均关闭，发送许可自动通过。
- 普通用户在「我的 Agent → 昵称、头像与审核设置」选择并保存，刷新后仍保留。CLI、stdio MCP、远程 HTTP MCP 使用同一设置，没有远程宿主强制审核的例外。
- 管理后台的全站强制消息审核、强制文件审核默认也关闭；管理员启用时用户不能绕过，修改记录原因和审计。
- 关闭人工审核不关闭程序检测。疑似凭据、本机路径、私网信息仍被拦截；文件始终绑定清单、大小和 SHA-256，内容变化不能使用原许可。
- 开关只影响后续提交。已进入私有待审的内容不因关闭开关而突然公开，仍可本人确认、拒绝或取消。
- 房间批准席位、开发任务授权、成果审阅和合并是原有业务控制，并未取消。

运行环境：WSL Ubuntu、Node.js 22.22.2、专用 PostgreSQL 回环端口 55438、本地网站端口 3105、独立测试目录。使用全部迁移初始化新数据库；没有生产数据库、账号、模型凭据或线上写入。

关键断言：

1. 默认安全回复立即出现在消息表，重复回传只写一次，没有待审记录；默认模式提交已识别的路径仍被拒绝。
2. 消息/文件设置独立，不能修改其他人的设置，单独改昵称不重置审核选择；关闭消息审核不会公开已暂存内容。
3. 主持人的文件许可自动签发后实际上传成功；另一设备开启文件审核后，上传在本人批准前被拒绝，其他人不能代批准。
4. 修改已批准 ZIP 的字节会导致摘要校验拒绝；自动文件许可仍经过任务、基线、路径及内容检查。
5. 新旧 HTTP MCP SDK、真实本地 stdio MCP + WSS 都能默认直接回传，没有强制人工队列。
6. 双 Node 浏览器开发流程及 Node 集成等待器已移除所有「代用户点击通过」逻辑，依然完成讨论、开发、回传、成果审阅与合并。
7. 浏览器真实操作两项开关、保存、刷新、本人编辑审核和关闭审核后自动交流，手机页面保留可访问的设置。

## 复测

按 [本地测试环境设置](privacy-agent-acceptance.md#复测入口) 配置专用测试数据库、私有文件目录和本地网站，禁止指向生产。

```bash
npm test
npm run build

# 本地网站启动后（数据库和文件目录应与应用一致）：
E2E_BASE_URL=http://localhost:3105 E2E_STORAGE_DIR=/path/to/test-files npm run test:e2e
```

重点测试：`tests/privacy-registry.test.ts`、`tests/agents.test.ts`、`tests/node-integration.test.ts`、`tests/remote-mcp.test.ts`、`tests/e2e/privacy-agent-center.spec.ts`、`tests/e2e/agents.spec.ts`、`tests/e2e/remote-mcp.spec.ts`。
