# 协作岛安装引导与统一配置

## 开始安装

在完整项目目录运行，已有网站先备份数据库、私有文件和安装配置，并停止 Web 服务。

- Windows：双击 `install.cmd`。推荐 PowerShell 5.1+；Windows x64 原生入口已提供，本次没有 Windows 实机验收，WSL 可使用下面的 Linux 入口。
- Linux/macOS：运行 `./install.sh`。
- 已有 Node.js 22+ 和 npm：也可运行 `npm run setup`。

启动文件检查 Node.js 与 npm。缺失或不满足版本时，从 Node.js 官方 HTTPS 下载固定版本 24.19.0，校验官方 SHA256 清单，安装到项目私有 `.data/node-runtime`，不修改系统 Node.js。下载、校验或运行失败会停止；不会关闭 TLS 验证。

安装器自动尝试打开浏览器，也会在终端显示本机安装地址。地址包含一次性安装凭证，不能分享。安装服务只监听 `127.0.0.1`；令牌从 URL Fragment 转入当前标签页 Session Storage，不发送给外部网站。安装界面不依赖 Next.js 或已经初始化的数据库。

## 引导流程

1. **环境检测**：系统/架构、Node/npm、内存、磁盘、可写配置目录、项目依赖、内置数据库条件及已有连接。尚无项目依赖时，点击“自动准备项目依赖”，程序使用锁文件和可写 npm 缓存执行 `npm ci`。
2. **数据库与文件**：选择内置 PostgreSQL 或已检测的实例，也可分字段填写或粘贴 PostgreSQL 连接字符串。填写私有文件绝对路径。
3. **网站与管理员**：设置名称、网站监听端口、浏览器访问来源、监听范围，以及首位管理员昵称、邮箱、密码。修改本机端口时，本机访问地址跟随更新；公开域名与内部监听端口分别配置。
4. **确认**：展示不包含密码的配置摘要，确认已有数据备份后执行。
5. **安装**：校验依赖、存储、数据库及实时通知，执行追加迁移，事务初始化管理员、网站设置与安装身份，保存配置，构建并启动网站，验证健康、配置接口及新管理员登录/后台权限。
6. **完成**：显示网站及后台入口。网站由独立运行进程管理，关闭浏览器或安装器不会停止网站。

新管理员密码为用户设置的 12–128 位字符串，数据库只存带随机盐的 scrypt 结果。填已有邮箱时必须提供原账号密码（至少 8 位）才能授权，不重置原密码。已有管理员时跳过创建，升级保留管理员和网站品牌，只有明确勾选时才更新品牌。

## 数据库自动识别

按可用信息发现候选，不扫描局域网或尝试猜测密码：

- `DATABASE_URL`、已保存安装配置、项目环境文件。
- 标准 PostgreSQL 环境变量 `PGHOST/PGPORT/PGDATABASE/PGUSER/PGPASSWORD`。
- 本机常见端口及 PostgreSQL Socket。
- 可读取时的 `pg_lsclusters`、PostgreSQL 监听端口、Windows PostgreSQL 服务配置、Docker PostgreSQL 发布端口。

有连接凭据的候选实际验证后自动推荐；多个候选由用户选择。发现端口不等于已经获得连接权限，未知账号/密码仍需填写。当前只支持 PostgreSQL 17+，不把 MySQL/SQL Server 当作兼容数据库。

连接检查包含版本、可写实例、Schema/函数/角色权限，以及两条独立连接的 LISTEN/NOTIFY。需要可执行迁移的账号：当前 bootstrap 包含创建角色与授权，需要 `CREATEROLE` 或足够的管理员权限、数据库 CREATE 和 SET ROLE。测试探针事务回滚，不留下探针表。

使用空的专用数据库或现有协作岛数据库。数据库包含其他应用的 public 表时拒绝作为安装目标。可选择“自动创建专用数据库”：上方连接维护库（如 `postgres`），填写新库名，账号需 CREATEDB；不会覆盖同名库。

外部模式只连接已有实例，不启动内置数据库。内置模式使用单独数据目录、端口和随机生成的数据库密码，监听本机，重启保留数据。不能以 root 启动内置 PostgreSQL；请使用普通用户或外部实例。

TLS 可选择本机/受信内网无 TLS，或验证证书的 TLS。提供商自定义 CA 可通过连接字符串的证书参数配置。拒绝 `sslmode=no-verify` 和全局关闭 TLS 验证。实时连接需要直连或 Session Pooler，不支持 Transaction Pooler。

## 地址如何统一生效

受保护配置默认在 `.data/installation/config.json`，包含安装 ID、数据库模式以及运行变量。管理员原始密码不写入这个文件。

| 配置                                      | 消费者                                          |
| ----------------------------------------- | ----------------------------------------------- |
| `DATABASE_URL`                            | 前后台 API、实时通知、迁移、管理员初始化        |
| `APP_ORIGIN`                              | 前后台来源校验、Session Secure Cookie、完成入口 |
| `PORT` / `ISLAND_BIND_HOST`               | dev/start、完整运行器、健康验证                 |
| `STORAGE_DIR`                             | 文件上传下载、后台存储健康与维护                |
| `PG_PORT/PG_DATA_DIR/PG_USER/PG_PASSWORD` | 内置数据库运行器                                |
| 可选外部存储、代理、备份变量              | 对应服务端适配器与后台状态                      |

浏览器继续使用同源 `/api` 和 SSE 路径，数据库凭据不进入客户端配置。地址变更通过运行配置生效，不把生产地址替换进源码。存储采用绝对路径，避免仓库目录和 Web 工作目录解析出不同位置。

统一读取顺序：安装配置优先于旧环境文件；尚未安装时使用已有进程环境和项目环境文件。根目录和 `apps/web` 的 `.env/.env.local` 均支持，Web 本地文件优先；支持常规变量引用与转义。

需要明确覆盖已安装配置时，设置 `ISLAND_ENV_OVERRIDES=DATABASE_URL,APP_ORIGIN` 并在进程环境提供相应值。必需配置不能覆盖为空；运行向导前应解除显式覆盖，避免保存的配置与实际进程不一致。不要将服务器变量放入 `NEXT_PUBLIC_*` 或 Next.js `env` 字段。

配置与控制令牌所在目录仅供运行账号使用：Unix 目录 0700、文件 0600，Windows 设置当前用户/SYSTEM 的目录 ACL。选择专用私有配置目录；配置备份也含数据库凭据，应按凭据保护。

## 日常启动、停止和自动启动

安装完成后：

```bash
# 启动内置数据库（如选用）及生产网站
npm run island:start
# 停止由本配置运行器启动的网站和内置数据库
npm run island:stop
# 查看健康状态
npm run island:status
```

也可使用 `start.cmd` / `./start.sh`；Linux/macOS 停止可用 `./install.sh --stop`，Windows 可用 `install.cmd -Stop`。

`npm run dev`、`npm start` 是 Web 启动方式，也读取保存的端口/来源/数据库；数据库需已运行。`npm run db:start` 自动区分内置启动或外部连接迁移，`npm run db:migrate` 和 `npm run admin:init` 使用同一连接配置。原有分别运行数据库/Web 的开发流程仍可使用。

向导可选“登录操作系统后自动启动”：Linux systemd 用户服务、Windows 当前用户计划任务、macOS LaunchAgent。没有权限或用户服务不可用时明确失败，可取消选项后重试。Linux 用户服务不是无需登录的系统级开机服务；服务器长期运行可使用现有系统级服务/容器管理。可单独执行 `npm run service:install`，`--dry-run` 仅生成配置。

配置/控制状态默认同在 `.data/installation`，运行日志在 `logs/runtime.log`。`ISLAND_CONFIG_FILE` 可以指定专用私有配置目录中的配置文件，`ISLAND_ROOT` 指定项目根目录；不要将配置指向仓库根目录或系统根目录。

## 升级与失败恢复

重新启动安装器会检测已有配置，进入保留数据升级。升级前运行 `npm run island:stop`；如果是手工启动的 Web，停止相应服务。升级不重置数据库，不修改旧迁移，不重置管理员密码，不清空聊天/文件。

安装过程中失败会展示阶段、原因及脱敏日志。重试复用已有迁移和管理员；强制终止后重新启动会识别中断，允许修改配置后继续。若新库已创建但后续失败，保留该库，可取消“创建数据库”，改为连接该库重试。

数据库中的安装身份与完成状态是服务端依据；删除本地状态文件不会重新授予管理员。已有配置不能把“切换到空数据库”当作升级，目标属于其他安装也会拒绝。更换数据库服务器涉及数据迁移/恢复，应单独完成后再更新连接地址。

配置损坏时恢复 `.data/installation/config.json.backup` 或对应备份；不要删除 `.data` 排错。SQL 迁移逐文件事务执行，已经成功的文件不会重跑，失败文件回滚。数据库、磁盘配置和进程无法跨系统做单一事务，阶段检查及重试用于恢复。

## 远程服务器与 HTTPS

安装器不开放公网。远程使用 SSH 转发，例如 `ssh -L 4310:127.0.0.1:4310 user@server`，在本机打开终端提供的安装地址；相同端口映射保留 Host 校验。

网站绑定所有网卡时要求 HTTPS 来源；也可绑定本机并让现有反向代理转发。域名、证书与代理由实际部署环境提供，不能凭空生成可用域名。公开来源会自动请求健康接口，并核对安装 ID，DNS/证书/代理不正确会保留安装进度并提示修复。

代理转发到向导选择的网站端口，关闭 SSE 缓冲、保持长连接，上传体积与后台允许的文件大小匹配（目前可设至 500MB，另留 multipart 开销）。`TRUST_PROXY=true` 只能在代理覆盖来源头并禁止绕过代理直连时配置。备份、外部存储、2FA 的原边界见 [后台部署说明](admin-deployment.md)。

## 验收范围

实际验证环境为 Linux x64，Node.js 24.19.0、PostgreSQL 18.4、Next.js 16.3.8、Chromium。Windows/macOS 已提供启动、检测与用户自启适配，但未在这两种系统上执行原生实机验收；不声称已验证所有系统。没有执行公网域名/证书部署或外部 Supabase 验收。

见 [安装验收](installation-acceptance.md) 和 [后台验收](admin-acceptance.md)。
