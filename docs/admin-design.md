# 后台需求、适配与实施

基线：用户提供的《协作岛_后台管理系统设计文档_V0.1.pdf》及 9 张后台原型。原型示例数字、账号及未来连接不是生产数据。

## 适配结论

继续在同一个 Next.js 应用、同一个 PostgreSQL 实现 /admin；业务实体、Participant 身份、Task 状态、持久化 Event Cursor 沿用聊天系统。现有数据库为自托管 PostgreSQL，认证为 HttpOnly 服务端 Session，实时为 LISTEN/NOTIFY + SSE，文件为私有对象；后台显示实际链路，不能冒充 Supabase 托管服务。

新增迁移而不修改已执行迁移。新增用户限制、房间软删除/冻结、文件隔离，以及举报、公告、设置、灰度开关、管理员、审计、IP 规则与服务端遥测。旧账号、房间、消息、任务、附件保持关联。写入统一走事务命令，后台动作同事务生成 Audit、Room Event 及持久化全局控制事件。普通客户端持续刷新全局能力，房间 SSE 补齐状态。

## 路由与固定权限

- /admin：真实概览、注册/活跃趋势、漏斗、风险与最近操作。
- /admin/users、rooms、content、reports、files、invites：超级/运营管理员；敏感正文必须明确定位和查看原因，记录 Audit。
- /admin/operations：网站品牌/信息/统计由超级管理员修改；运营可维护公告。功能开关由超级/技术管理员管理。
- /admin/system：超级/技术管理员；健康、实时连接、Event、错误、存储、维护及 CSV。
- /admin/security、audit：超级管理员管理角色和 IP，超级/运营可撤销用户 Session，技术可查看安全/审计诊断。
- /admin/agents：实际 Node/Gateway 未上线，服务端拒绝并且导航隐藏。

## 联动验收

用户封禁撤销全部会话并拒绝登录；限制发言/建房/上传同时影响前台和 API。房间冻结保留读取并禁用写入；删除可恢复且不可访问；主持人转移、成员移出、任务重新分配同步到前台。消息软删除保留回复关系；文件隔离保留历史卡片并拒绝下载。邀请仅展示指纹，撤销即时失效。任务/上传开关支持全部、指定用户/房间、管理员测试及确定性百分比灰度；维护模式管理员仍可登录后台。

网站名称、Logo、Favicon、SEO、备案、页脚、联系信息、统计脚本与公告使用同一配置。后台默认不浏览所有消息。高风险操作明确对象、二次确认、必填原因；服务端再次验证角色和确认字段。最后一名超级管理员不能被撤销或封禁。

## 实施顺序

1. 追加迁移、事务业务规则、管理员初始化和授权。
2. 后台 API、全站配置和前台能力/状态联动。
3. 对齐原型的后台页面、详情抽屉、危险操作及真实图表。
4. 数据库权限测试、前后台多浏览器联动、构建检查和部署/验收文档。

备份和带宽必须来自真实基础设施，没有数据时明确显示未配置；不构建虚假备份与成本数字。病毒扫描继续保留钩子，Agent 继续保留协议边界。
