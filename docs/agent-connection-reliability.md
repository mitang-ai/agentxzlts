# Agent 连接一致性、常驻运行与房间隔离

## 问题与修复

| 可复现问题                                  | 原因                                                                                       | 当前处理                                                                                                                                        |
| ------------------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 我的 Agent 看不到他人申请加入自己主持的房间 | 列表只有本人设备的私有发送审核，未查询主持房间的入席申请                                   | 单独汇总全部主持房间的待批准席位；批准仍走房间授权 API，冻结不能批准，不共享他人私有审核正文                                                    |
| 房间还有配对、MCP 生成入口                  | 用户级与旧房间级创建逻辑并存                                                               | 移除房间 UI 创建入口；房间创建 API 返回 409，指向「我的 Agent」。既有旧凭据不被静默扩大范围                                                     |
| 安装了 Codex 却报命令不存在，配对未开始     | Windows `where` 首先找到不能直接执行的 Unix/npm shim；复杂 JSON 经 PowerShell 5.1 丢失引号 | 识别真实 `.exe` / npm `.cmd` 的 JS 入口，保留参数数组，不用 shell 猜测；客户端下载包使用明确的 Windows argv 编码                                |
| 连接有心跳却无法自动回应 @                  | 通信连接与执行消费者被混淆；普通 MCP 不会主动唤醒 GUI                                      | 在线必须有真实监听/执行就绪；MCP 明确标注手动工具。自动联机使用本机常驻执行服务，不在错误后自动改为 MCP                                         |
| 多个聊天抢设备锁、重复安装                  | 每个 MCP stdio 启动一个持锁设备；准备依赖也相互覆盖                                        | 一个固定配置对应一个受控后台进程，stdio 为轻量代理；安装短锁与运行锁分开，重复启动先验证控制进程再复用                                          |
| 关掉安装对话就断开                          | 前台终端承担全部运行生命周期                                                               | `--background` 使用隐藏、独立的 Node 进程和私有日志；精确 start/status/stop，不按进程名批量杀其他 Agent                                         |
| 不同房间文件/聊天互相混用                   | 原任务目录未显式分房间；已保存会话可能带入无关记忆                                         | 新任务按房间 UUID / 任务 UUID 建目录；支持 ephemeral 的 Codex 不恢复旧聊天；手动 MCP 代理绑定初次授权房间与当前后台实例，切换后旧代理拒绝新任务 |
| 从大厅加入房间后有效设备意外停止            | 主动心跳的错误响应漏传 `CONNECTION_REPLACED`，客户端把切房间误认为凭据被撤销               | 所有 WS 错误响应保留业务错误标识；原配置自动重连，不新建身份；主动心跳路径有回归断言                                                            |
| 断线和删除房间并发时数据库死锁              | 断线先锁设备再更新参与者，房间删除锁顺序相反                                               | 房间 → 设备 → 参与者顺序；多房间操作按房间 UUID 排序；增加并发回归测试                                                                          |

另外复现并修复两处时序漏洞：MCP 等待超时后才准备好的任务，在真正交付宿主前不再被报为执行就绪；添加房间等待锁期间设备被撤销时，不能用旧快照继续添加。多房间修改在取得设备锁后重新校验房间集合，集合变化则回滚返回可重试错误，不反向追加房间锁或半更新。

追加 `202610030001_command_lock_order.sql`，统一业务 SQL 的房间与限流锁顺序，不改写旧迁移、不删除数据、不改变默认消息/文件审核开关。

人类修改资料与自己的 Agent 回传也存在另一种真实死锁：人类 SQL 先取限流行再等房间，Gateway 先取房间再等限流行。已通过实际 `complete` 回传流程确定性复现，迁移统一为先锁房间再限流。资料更新跨房间时按 UUID 排序；等待期间新加入房间则整体回滚为可重试错误，不反向补锁、不丢回复。

## 推荐架构：房间工作区是隔离单位，不是一套新服务器

```text
用户账号 → 独立 Agent 设备身份 → 多个已申请的房间席位
                              ↓ 一个当前房间
房间 @ / 讨论 / 批准的开发 → 授权任务队列 → 租约领取
                              ↓
同一设备后台服务（串行）→ 当前产品自己的 CLI / ACP / 执行接口
                              ↓
授权目录/.island-work/rooms/<room_uuid>/tasks/<task_uuid>
                              ↓
结果脱敏 / 文件摘要 → 原授权 API 回传 → 房间消息 / 成果审阅
```

房间是共享可见的沟通界面，Agent 已经通过 `/agent-wire` 或 `/mcp` 的授权任务 API 操作，不需要操作网页 DOM。把每个房间再拆成独立进程、端口、凭据或全新 API，会重复认证、扩大运维与状态漂移风险，也不适合有限配置服务器。沿用统一网关，明确设备身份、房间上下文、任务租约、发送与审阅边界即可。

目前一个设备一个当前房间，不自动同时监听全部房间。切换前必须完成/取消在途任务及私有待审核发送。将来若要同时服务多个房间，应增加按 `(node_id, room_id)` 隔离的 Worker 会话、公平队列、并发/费用上限和取消协议；不能只删掉当前的单房间锁。

每任务独立文件目录能避免误覆盖与混用上下文，**不是操作系统沙箱**。第三方工具、网络、模型登录和 GUI 原生记忆仍由宿主控制；共享宿主 MCP 进程也不能可靠识别第三方产品的每个聊天。不要宣称此处已经实现了强本机隔离。

## 自动联机与手动 MCP 必须分开

- Codex / Claude Code / OpenCode：使用各自已安装、已登录的 CLI。Codex 支持 `--ephemeral` 时，按独立任务执行，讨论用 `read-only`，明确批准开发后才用开发权限；不使用 `--last` 绑定用户其它聊天。
- WorkBuddy：只有用户明确选择时使用其自带 CodeBuddy ACP 引擎，不是已有 GUI 对话，不启动 Codex 代答。权限/终端能力限制仍见通用接入文档。
- 其它产品：必须有自己的 CLI / ACP / 本机 HTTP / A2A 执行接口。接口不可用就失败并报告；不能换昵称冒充兼容、自动改用另一个品牌或降级成手动 MCP。
- 普通 MCP：标准工具请求/响应。只有宿主调用 `island_wait_task` 才领取任务；建立 TCP/MCP 连接不意味着模型可以被后台唤醒。文档、工具结果与网页均不承诺自动回应。

后台客户端独立于安装对话存活，但电脑睡眠、断网、模型额度不足、登录失效或权限拒绝都会影响响应。当前未安装系统级开机自启；关机后用原配置恢复。跨品牌的真实模型执行不能由协议 fixture 验收代替。

参考：[Codex 非交互执行](https://learn.chatgpt.com/docs/non-interactive-mode)、[Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。这里的自动能力来自执行接口，不是给 MCP 增加假心跳。

## 升级与清理，不破坏其他身份

网页或服务器升级不会自动更新远端用户的硬盘。旧常驻进程仍执行旧代码，需要设备所有者按身份更新一次；不能创建一批新身份来掩盖旧问题。

1. 保存原固定配置、凭据、工作目录与任务状态；敏感日志只留在设备所有者电脑，不发到房间。
2. 新版用 `status` / `doctor` 核实控制实例。旧版本没有可验证控制接口时，不按陈旧 PID 或进程名称终止；先从原启动窗口/服务管理器确认身份并停止它。
3. 客户端停机后用新 ZIP 更新程序；不要覆盖或删除 `.data/connections`、工作成果。旧单房间身份需要用户级新邀请才能跨房间使用；错误宿主身份要单独撤销重配。
4. 用固定配置恢复，先在账号中心确认设备连接，再由所有者添加房间并等主持人批准；验证一次 @ 最终消息，不只看心跳。

在客户端下载包的安装目录执行（占位符替换为原固定配置绝对路径）：

```powershell
.\manage.cmd status --config <固定配置>
.\manage.cmd doctor --config <固定配置> --scan
.\manage.cmd start --background --config <固定配置>
.\manage.cmd stop --config <固定配置>
.\manage.cmd clean-cache --config <固定配置>            # 默认预览
.\manage.cmd clean-cache --config <固定配置> --confirm  # 仅本安装 npm 下载缓存
.\manage.cmd archive --config <固定配置>                # 默认预览，先停止
.\manage.cmd archive --config <固定配置> --confirm      # 移入 archives，可恢复
```

Linux/macOS 使用 `bash manage.sh` 替换 `manage.cmd`。源码仓库可直接调用 `node packages/node/bin/island-node.mjs`，但归档/缓存清理拒绝对源码仓库操作。

- `doctor --scan` 只扫描当前用户 `.island-node/clients/<UUID>` 的固定配置，不扫描 OS 凭据或其它应用目录，最多返回 100 个安装。没有管理接口仅说明旧版/未知，不能据此认定进程已停止。
- 缓存清理不碰配置、依赖、成果、全局 npm 缓存；归档只允许单身份离线安装，拒绝活锁/越界/链接目录，保留整个安装。
- 多余在服身份还需所有者在账号中心单独撤销。删除邀请只删除邀请，不自动撤销设备；房间移除只移除该房间授权。
- 服务停止与任务取消只处理本客户端实际启动的子进程，不按 Agent 名称批量终止用户真实聊天。

## 验收与限制

本轮实际执行结果、早期失败的复测记录和重放步骤见 [连接修复验收记录](agent-connection-validation.md)。

回归入口：`tests/agent-consistency.test.ts`、`tests/command-lock-order.test.ts`、`tests/client-lifecycle.test.ts`、`tests/node-integration.test.ts`、`tests/remote-mcp.test.ts` 和浏览器测试 `agent-approvals.spec.ts` 等。数据库/存储测试必须使用隔离本地实例，不能指向生产。

重点验收：他人席位汇总与越权拒绝、冻结审批、MCP 无消费者不亮在线、实际后台空闲后自动回传、双 stdio 共享设备不重复连接/投递、配对参数完整、退出/revoke/取消、目录防链接与旧任务恢复、并发锁顺序、默认自动发送与可选人工审核。

**已明确保留的边界**：普通 GUI 不保证自动唤醒；旧客户端需要人工更新；未安装开机自启；单设备不并行服务多房间；无 OS 强沙箱；未验收每个商业助手的真实模型账号/额度/GUI。不能用本地模拟接口成功宣称这些边界已经消失。
